
"follow the harness skill" may load `CLAUDE.md` without loading the Skill body; such a run is not GREEN evidence.

### Vague login false-green — RED → GREEN

Pressure state: the raw request was only `想做个简单的登陆`; the user added time pressure and asked Main to
fill reasonable defaults, confirm topology once, and finish Clarify.

Before predicate-bound scoring, the observed run invented Identity Store/Auth Backend/Session components,
marked code/docs not-required, assigned every dimension 5/5, and treated topology confirmation as sufficient.
After the first predicate wording change, Sonnet still listed six pending authentication decisions while assigning
all dimensions 4/5 and calling the request Fast Path. This was the concrete rationalization used to tighten the
algorithm: score from an empty predicate set, pending surfaces cap affected dimensions below 4, and time pressure
is not scope confirmation.

The final greenfield/facts-complete run produced:

```text
Topology: one login-capability outcome; credential/session remain decision surfaces
Goal/Scope/Constraints/Acceptance/Context: every dimension below 4
Authentication surfaces: pending; Fast Path: not applicable
Round 0: topology confirmation only; no nested credential/stack question
```

The mechanical finalizer also rejects a score 5 row without complete predicate coverage, evidence-ledger refs,
exact clause provenance, and explicit `confirmed`. One vague clause cannot be reused or self-declare support for the
whole scorecard; authentication requests (including sign-in aliases) cannot finalize without all six decision-surface rows.

The production report in Issue #74 was the baseline RED: after `expired-session-lease`, Main invented
`workflow clear-lease` and `workflow abort`, searched internal files, and finally tried to create the change directory
manually. With the recovery contract loaded, the same scenario produced exactly one action:

The observed GREEN treated this as an idempotent renewal of the existing change. For a subsequent
